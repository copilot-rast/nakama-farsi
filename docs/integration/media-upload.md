# Jazebe media upload adapter

The Nakama Go module uses Nakama's existing client listener. A signed-in client first calls `jazebe_media_upload_begin` with `planetId`, `purpose` (`evidence`, `avatar`, or `mission_media`), `fileName`, and `expectedBytes`. The RPC returns `uploadId`, a token scoped to one upload, `chunkBytes` (131072), and the chunk and completion paths. The RPC checks the Nakama user: evidence and avatar require an active planet membership; mission media requires an active brand administrator. The token expires after 15 minutes and is stored only as a SHA-256 digest.

Upload the exact declared number of bytes in sequential `POST` requests to `chunkPath`. Each request has `X-Jazebe-Upload-Token`, `X-Chunk-Index` starting at `0`, and raw bytes as its body. Each chunk must be at most 131072 bytes. Then `POST` to `completePath` with the same token. Completion verifies total length, hashes all chunks, and checks actual file signatures. Evidence accepts image or MP4 up to 25 MiB; avatar accepts image up to 5 MiB; mission media accepts image or MP4 up to 50 MiB. The response includes an `id` and a public random-ID URL. Submit evidence using its `id` in `mediaIds`; only uploads owned by the same user and planet with `purpose=evidence` are accepted. `jazebe_media_upload_delete` withdraws an owned upload.

Ticket issuance is limited to 20 uploads per Nakama user per 60 seconds by default, using PostgreSQL advisory locks for multi-node consistency. `JAZEBE_MEDIA_UPLOAD_PER_MINUTE` changes the limit (1–10000); invalid values stop module registration. The custom HTTP handlers do not inherit Nakama RPC authentication. Keep the ticket private, send it only in the upload header, and do not place it in query strings or logs. A completed upload clears its ticket hash. Public media delivery uses an unguessable UUID URL like the source public media route and supports byte ranges. Uploaded bytes live in PostgreSQL chunks so all Nakama nodes can serve them. This has storage and backup costs; a future object-store adapter can replace the chunk repository without changing the mission evidence contract.

Run `integrations/jazebe/reconcile` daily. It deletes expired incomplete uploads and withdraws unreferenced completed evidence after seven days, then purges withdrawn, unreferenced uploads after a further day. It retains media referenced by any completion (including a soft-deleted completion), mission configuration, or Nakama user avatar URL. Avatar retirement and full profile integration remain pending; the sweep does not automatically withdraw avatar media. Live PostgreSQL and Nakama HTTP tests have not run in the current environment.
