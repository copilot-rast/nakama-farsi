# Planet group invitation links

The native group integration stores planet-scoped groups using Nakama user IDs. An active group member may call `jazebe_group_invite_create` with `planetId` and `groupId`. It returns a 43-character token, an expiration timestamp seven days later, and a `/g/<token>` link. Set `JAZEBE_MAIN_APP_URL` to the user application's public base URL to return an absolute link; otherwise the URL is relative. The database stores only a SHA-256 token digest.

`jazebe_group_invite_preview` returns the link's status, planet and group details, inviter display name, and the caller's current membership without joining. `jazebe_group_invite_join` joins a valid, active group directly, even when its regular join mode requires approval. The transaction creates the planet membership with `group_invite_link` provenance if needed, takes the group seat, cancels any pending group request, records group activity and increments link use count. Repeating acceptance as an existing group member does not consume another use. `jazebe_group_invite_revoke` is limited to the token creator or an active group manager. A member's links are revoked when they leave.

The migration also projects the source product active flag onto `jazebe_brand.is_active`, defaulting to true. Brand deactivation and source invite-mission token attribution remain to be integrated. The invite RPCs have pure guard tests and compile, but have not run against PostgreSQL or a live Nakama process in this environment. Do not treat link flows as fully verified until expiry, revocation, concurrent joins, capacity, and brand/planet availability have been exercised on PostgreSQL.
