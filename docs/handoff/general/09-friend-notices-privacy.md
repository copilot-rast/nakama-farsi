## اعلان‌ها

دو اعلان ماندگار تازه در صندوق پیام (Nakama notifications). روی سوکت هم زنده می‌رسند.

| کد اعلان | چه وقت | به چه کسی |
| --- | --- | --- |
| `1130` | درخواست دوستی رد شد | فرستندهٔ درخواست |
| `1131` | دوستی حذف شد | بازیکنی که حذف شد |

`subject` متن آماده به زبان گیرنده است. `sender_id` بازیکنی است که رد یا حذف کرده. `content`:

```json
{ "code": "FRIEND_REQUEST_DECLINED", "userId": "<user id>", "name": "آرش" }
```

`code` برای `1131` برابر `FRIEND_REMOVED` است. لغو درخواست توسط خود فرستنده، رد خودکار درخواست‌های منقضی و بلاک کردن اعلان ندارند. ادمین هر دو اعلان را در تنظیمات پروژه ← دوستی خاموش یا روشن می‌کند (پیش‌فرض روشن).

## وضعیت آنلاین فقط برای دوستان

اگر ادمین روشن کند (پیش‌فرض خاموش)، `StatusFollow` فقط دوستان را دنبال می‌کند و بقیهٔ شناسه‌ها بی‌صدا حذف می‌شوند. خطایی برنمی‌گردد؛ فقط وضعیت غریبه‌ها نمی‌آید. برای این‌که خودِ بازیکن در وضعیت دیگران دیده شود، سوکت را با `status=true` باز کنید.

## پیام خصوصی فقط بین دوستان

اگر ادمین روشن کند (پیش‌فرض خاموش)، باز کردن گفتگوی خصوصی (`ChannelJoin` نوع ۲) و فرستادن پیام در آن فقط بین دو دوست ممکن است. اگر دوستی بعداً حذف شود، پیام بعدی هم رد می‌شود.

خطا یک JSON است:

```json
{ "code": "FRIENDSHIP_REQUIRED", "message": "پیام خصوصی فقط بین دوستان است.", "lang": "fa", "meta": { "userId": "<user id>" } }
```

وضعیت هر دو قانون در `base_friend_rules` هم می‌آید: `presenceFriendsOnly` و `dmFriendsOnly`. دکمهٔ پیام خصوصی را برای غیر دوستان از روی همین مخفی کنید.
