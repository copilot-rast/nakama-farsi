title: خطاهای تنظیم فروشگاه دیگر «خطای شبکه» نیستند
titleEn: Store setup errors are no longer network errors
summary: STORE_CONFIGURATION_REJECTED و METHOD_UNAVAILABLE حالا کد ۹ (FAILED_PRECONDITION) دارند و تکرار نمی‌شوند؛ کنسول کلیدهای فروشگاه را می‌آزماید
---

وقتی فروشگاه (بازار، مایکت، گوگل یا اپل) کلید سرور را رد می‌کند، خرید بازیکن روی سرور «در انتظار» می‌ماند و بعداً تحویل می‌شود. تا امروز سرور این حالت را با کد ۱۴ (UNAVAILABLE، HTTP 503) جواب می‌داد و بازی آن را خطای موقت شبکه می‌دانست و یک دقیقه تکرار می‌کرد. حالا جواب دائمی است.

## کدها

| کد | قبلاً | حالا | معنی برای بازی |
|---|---|---|---|
| `STORE_CONFIGURATION_REJECTED` | ۱۴ / HTTP 503 | ۹ / HTTP 400 (در فهرست خطاها 412) | تنظیم فروشگاه روی سرور مشکل دارد. تکرار نکنید، خرید را مصرف (consume) نکنید، به بازیکن بگویید خریدش ثبت شده و بعداً می‌رسد. |
| `METHOD_UNAVAILABLE` | ۱۴ / HTTP 503 | ۹ / HTTP 400 (412) | این روش پرداخت روی سرور فعال یا کامل نیست. |
| `STORE_MODE_CHANGED` | ۱۴ / HTTP 503 | ۹ / HTTP 400 (412) | فروشگاه روی سرور در حالت آزمایشی است. |
| `STORE_UNAVAILABLE` | ۱۴ / HTTP 503 | بدون تغییر | فروشگاه در دسترس نبود؛ تکرار درست است. |
| `PURCHASE_INVALID` | ۹ | بدون تغییر | فروشگاه این خرید را نمی‌شناسد (مثلاً توکن ساختگی). |

خرید در انتظار با `economy_purchase_review` در شروع بعدی بازی (یا با `economy_purchase_submit`) دوباره بررسی و تحویل می‌شود؛ یک توکن هیچ‌وقت دو بار جایزه نمی‌دهد.

## کنسول

«تنظیمات پروژه ← درگاه‌های پرداخت»، کارت هر فروشگاه:

- **آخرین خطای فروشگاه**: زمان، کد HTTP و پاسخ خود فروشگاه (بدون کلید و بدون توکن).
- **آزمودن کلیدها**: سرور با یک توکن ساختگی از فروشگاه می‌پرسد. «کلیدها درست است» یعنی فروشگاه گفته خرید پیدا نشد؛ بقیهٔ جواب‌ها: کلید رد شد، نام بسته پیدا نشد، شناسهٔ محصول پیدا نشد، فروشگاه در دسترس نبود.
- **بررسی دوبارهٔ خریدهای مانده**: بعد از درست کردن کلید، خریدهای در انتظار و منقضی‌شدهٔ ۳۰ روز اخیر را با آخرین توکنی که بازی فرستاده دوباره بررسی می‌کند.

در جزئیات هر پرداخت، ردیف «آخرین پاسخ فروشگاه» و دکمهٔ «بررسی دوباره با فروشگاه» هست. در Ctrl+K هم «آزمودن کلیدهای فروشگاه» را بنویسید.

## پکیج یونیتی

از نسخهٔ `3.23.0-nf.7`، `PaymentClient` با این کدها فوراً می‌ایستد و `PurchaseResult` با `Outcome = Pending` و `IsStoreNotReady = true` برمی‌گرداند (کد در `Error`). خرید مصرف نمی‌شود و `RecoverAsync` در شروع بعدی آن را تحویل می‌گیرد.
