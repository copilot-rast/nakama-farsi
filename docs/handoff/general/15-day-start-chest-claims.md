همهٔ این‌ها تنظیم ادمین هستند و پیش‌فرض‌شان رفتار قبلی است. RPCها همان قبلی‌اند؛ فقط فیلد و خطای تازه دارند. روی سوکت با `callRpc` بفرستید.

## جایزه‌ای که صندوق باز می‌کند

یک جایزه (XP road، جایزهٔ روزانه، خانهٔ گردونه، پیشنهاد، کد هدیه و …) می‌تواند ردیف `chest` داشته باشد. صندوق همان لحظهٔ گرفتن جایزه باز می‌شود و نتیجه‌اش در همان جواب و همان پرداخت است. در `rewards` جواب، ردیف صندوق این شکل را دارد:

```json
{
  "type": "chest",
  "key": "chest-1",
  "action": "open",
  "value": 1,
  "rewards": [
    { "type": "currency", "key": "coin", "action": "add", "value": 154 },
    { "type": "currency", "key": "gem", "action": "add", "value": 4 }
  ]
}
```

- `value` یعنی چند بار باز شد.
- `rewards` همان چیزی است که به کیف پول رفت. برای انیمیشن صندوق همین را نشان دهید.
- اگر همان جایزه دوباره خوانده شود (مثلاً `economy_rewards_mine`)، همان نتیجه برمی‌گردد.

ردیف ارز ممکن است مقدار تصادفی داشته باشد. در تعریف جایزه `"action": "random", "value": { "min": 150, "max": 180 }` است؛ در جواب گرفتن جایزه، مقدار قطعی با `"action": "add"` می‌آید.

## جایزهٔ روزانه (زنجیره)

### شمارش با آنلاین بودن

اگر رویداد زنجیره `online` باشد، روز با وصل بودن به سرور شمرده می‌شود: هم موقع وصل شدن سوکت و هم وقتی روز تازه شروع شود و سوکت هنوز وصل است. کافی است سوکت باز بماند؛ RPC جدایی لازم نیست.

### شروع روز

زنجیره می‌تواند ساعت شروع روز خودش را داشته باشد (مثلاً ۰۱:۳۰ UTC). در `economy_streaks` این فیلدها هست:

| فیلد | معنی |
| --- | --- |
| `dayZone`, `dayStartMinute` | منطقهٔ زمانی و دقیقهٔ شروع روز (۹۰ یعنی ۰۱:۳۰) |
| `nextPeriodAt` | لحظهٔ شروع روز بعد |
| `claimWindow` | `open` یا `period` |
| `signupDelayDays` | چند روز اول بعد از ثبت‌نام جایزه ندارد |

### مهلت گرفتن

با `claimWindow: "period"`، جایزهٔ هر روز فقط تا آخر همان روز گرفتنی است:

- ردیف روز `status: "expired"` می‌گیرد و از `claimable` بیرون می‌رود.
- در `economy_rewards_mine` جایزه `expiresAt` دارد و بعد از آن `status: "expired"`.
- اگر بعد از مهلت `economy_reward_claim` بفرستید:

| کد | کار اپ |
| --- | --- |
| `CLAIM_EXPIRED` (`status` 410، `meta: { expiredAt }`) | جایزه را به‌صورت «از دست رفت» نشان دهید |

### تأخیر بعد از ثبت‌نام

در روزهای `signupDelayDays`، زنجیره جلو می‌رود ولی جایزه‌ای ساخته نمی‌شود؛ پس `claimable` خالی است.

### مرحلهٔ بی‌پایان با جایزهٔ گرفتنی

وقتی `infinity.mode` برابر `claim` است، هر روزِ بعد از پایان چرخه یک جایزهٔ گرفتنی می‌سازد (به‌جای پرداخت مستقیم):

```json
"phase": "infinity",
"infinity": { "mode": "claim", "prizeId": "…", "claimId": "…", "status": "claimable" }
```

`claimId` را با `economy_reward_claim` بگیرید. مهلت آن هم مثل روزهای دیگر است.

## بازی شانس: نوبت رایگان روزانه، «اول نوبت رایگان»، قفل سطح

در `economy_chance_game` و `economy_chance_games` این فیلدها اضافه شده:

| فیلد | معنی |
| --- | --- |
| `freeReset` | `interval` (چند دقیقه بعد از نوبت قبلی) یا `daily` (یک نوبت رایگان در هر روز) |
| `freeFirst` | `true` یعنی تا نوبت رایگان امروز مانده، بلیت پذیرفته نمی‌شود |
| `dayEndsAt` | پایان روزِ این بازی (برای سقف روزانه، پلکان قیمت و نوبت رایگان روزانه) |
| `minLevel`, `level`, `locked` | فقط وقتی بازی شرط سطح دارد |

خطاهای تازه:

| کد | کار اپ |
| --- | --- |
| `CHANCE_LOCKED` (`status` 403، `meta: { minLevel, level }`) | قفل و سطح لازم را نشان دهید |
| `CHANCE_PRICE_CHANGED` با `meta: { amount: 0, expected, freeFirst: true }` | اول نوبت رایگان را با `economy_chance_play` بازی کنید |

`nextPlayTime` و `nextPlayAt` برای `daily` تا شروع روز بعد است.

## پیشنهاد ورودی بعد از بازی تمام‌شده

شرط تازهٔ پیشنهاد ورودی `game` است: وقتی بازیکن چند بازی را تمام کرده باشد (برد، باخت یا تمام شدن وقت؛ ترک بازی و بازی بازگشت‌خورده حساب نمی‌شود). پیشنهاد همان لحظهٔ پایان بازی ساخته می‌شود و زمان‌سنج از همان لحظه شروع می‌شود. در `economy_offers` مثل بقیهٔ پیشنهادهای ورودی با `expiresAt` و `secondsLeft` می‌آید.

## روز اجتماعی

`base_friend_rules` حالا `dayStartMinute` و `timeZone` روز اجتماعی را برمی‌گرداند. سقف درخواست روزانه، پیشنهاد دوستی و `resetsAt` با همین روز حساب می‌شوند.
