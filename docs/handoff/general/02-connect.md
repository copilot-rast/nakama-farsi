اپ فقط با سرور بازی حرف می‌زند. کنسول مدیریت جای ادمین است و اپ هیچ‌وقت آن را صدا نمی‌زند.

## چیزهایی که لازم دارید

مقدارهای همین سرور در بخش [اطلاعات اتصال](#connection) بالای همین بخش آمده است.

| چه چیزی | مقدار |
| --- | --- |
| میزبان سرور بازی (host) | `{{SERVER_HOST}}` |
| پورت | `{{SERVER_PORT}}` |
| SSL | `{{SERVER_SSL}}` |
| کلید سرور (server key) | `{{SERVER_KEY}}` |

آدرس سرور بازی همان آدرسی است که بازی به آن وصل می‌شود، نه آدرس کنسول. کلید سرور داخل بیلد اپ هم هست، پس رمز به حساب نمی‌آید.

با کلاینت جاوااسکریپت Nakama:

```ts
import { Client } from '@heroiclabs/nakama-js';

const client = new Client('{{SERVER_KEY}}', '{{SERVER_HOST}}', '{{SERVER_PORT}}', {{SERVER_SSL}});
```

هیچ کلید دیگری نباید در باندل اپ باشد: نه کلید HTTP، نه رمز کنسول، نه کلید کنسول. مسیرهای `/v2/console/...` مال ادمین است.

## نشست

1. اپ با باز شدن، با شناسهٔ دستگاه یک نشست مهمان می‌سازد.
2. ورود روی HTTP است. کلید سرور نام کاربری Basic است و رمز خالی:

```ts
const SERVER_KEY = '{{SERVER_KEY}}';
const basic = 'Basic ' + btoa(`${SERVER_KEY}:`);
```

3. توکن و refresh token را نگه دارید و قبل از انقضا نشست را تازه کنید.
4. شناسهٔ بازیکن همیشه از نشست خوانده می‌شود. هیچ RPCای `userId` خود بازیکن را در بدنه نمی‌خواهد.

## اول سوکت، بعد HTTP

همهٔ RPCها را روی سوکت صدا بزنید. روی سوکت، اتصال و احراز هویت یک بار انجام می‌شود و هر فراخوانی فقط یک پیام کوچک است.

| وضعیت | کار اپ |
| --- | --- |
| سوکت وصل است | فراخوانی روی سوکت |
| سوکت وصل نیست | همان فراخوانی روی HTTP. درخواست هنوز به سرور نرسیده، پس تکرارش بی‌خطر است |
| فراخوانی رفت ولی جواب نیامد | خواندنی را یک بار روی HTTP تکرار کنید. نوشتنی را خودکار تکرار نکنید؛ اول وضعیت را از سرور بخوانید |
| سرور خطا داد | همان خطا را نشان دهید. خطای سرور را روی HTTP تکرار نکنید |

ورود و تازه کردن نشست روی HTTP می‌ماند. پرداخت هم روی HTTP است، چون انتقال به درگاه و برگشت از آن کار مرورگر است.

## شکل فراخوانی روی HTTP

هر RPC یک مسیر دارد. بدنه همان شیء درخواست است و جواب همان شیء جواب:

```http
POST /v2/rpc/<id>?unwrap=true
Authorization: Bearer <session token>
Content-Type: application/json
```

روی سوکت همان `id` و همان بدنه را بفرستید.

## اتصال دوباره

* سوکت را فقط بعد از داشتن نشست بسازید. با عوض شدن نشست (ورود یا خروج)، سوکت قبلی را ببندید و دوباره وصل شوید.
* اگر سوکت قطع شد، با فاصلهٔ ۱، ۲، ۴، ۸ و بعد هر ۱۵ ثانیه دوباره وصل شوید. در این مدت RPCها روی HTTP کار می‌کنند.
* بعد از هر اتصال دوباره، چیزهای زنده (شمارندهٔ اعلان، وضعیت بازی) را دوباره از سرور بخوانید.
