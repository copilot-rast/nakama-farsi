# nakama-farsi change log

Changes of this fork on top of heroiclabs/nakama. The upstream `CHANGELOG.md` stays as heroiclabs writes it.

Releases are tagged on `main` as `v3.42-fa.N`: the upstream version this fork is based on, then a running number (`v3.42-fa.1`, `v3.42-fa.2`, …; after merging upstream 3.43 the next one is `v3.43-fa.1`). Each tag gets a GitHub release whose notes copy the entry below. Game forks see these tags and releases first on their «به‌روزرسانی‌ها» page, so write every entry for the people who merge it: what changed, new migrations, new environment variables, and anything they must do by hand.

## [Unreleased] — on `dev`, based on heroiclabs/nakama `37618ad4` (3.42.0 + master of 2026-11-12)

### Added
- Username change policy (off by default): first change free, a price ladder in an economy currency (defaults 50, 100, 200, 400, 800 gems), hours between changes, `base_username_quote`, `base_username_change {username, expectedCost?}`, UpdateAccount charges the same way, staff rename from the player card without price or wait, history of every change (`base_username_change` table) and an `account` activity entry.
- Player codes: every account gets a short public code (6 upper-case letters and digits by default, set in «قوانین حساب») from a database trigger; `base_my_code`, `base_player_codes`, `base_user_by_code` with the relationship and online state for friends; friend RPCs take `codes`; console player search finds codes.
- Friend notices and privacy: inbox notices 1130 (request declined) and 1131 (removed as a friend), each with its own switch (on); «وضعیت آنلاین فقط برای دوستان» filters StatusFollow and «پیام خصوصی فقط بین دوستان» refuses DM joins and messages with `FRIENDSHIP_REQUIRED` (both off).
- Friend suggestions: a daily list per player from co-players (recorded from finished games registry matches), mutual friends, similar activity (presence days) and an optional level table, with visible and reserve sizes, quotas, fading after repeated shows, live co-play patch, admin settings and a rebuild from the player card; `base_friend_suggestions`.
- Persian console: fa-IR with RTL and Persian digits, the Plane look (rail, sidebar per section, Yekan Bakh, Phosphor icons, light and dark), Ctrl K page search, branding and a first-login setup wizard, one project settings window with every section.
- Accounts: phone and SMS login with sandbox codes, account rules, app versions with forced update, countries.
- Players and chat: player tags, suspensions, mutes and warnings, a Persian-aware word filter, player reports.
- Events and economy: currencies, metas, prizes, shop with ZarinPal/Bazaar/Myket, gift codes, player events, event prizes, meta rules, level tables, streaks.
- Streak milestones: safe days a missed day never drops below, one-time milestone prizes, an option to pay day rewards again after a fall.
- Tasks and task groups with sub-tasks, repeats and dependencies.
- Items and inventory with buy, unlock, upgrade, equip and services; product rules.
- Achievements with tiers, progress, hidden badges and per-tier prizes.
- Banners and banner placements with schedules and player targeting.
- Chance game (wheel, loot box, slot) and prize groups.
- Sponsors with sponsored banners, a report and CSV export.
- Notifications: in-app inbox, push (FCM HTTP v1 and a log sandbox), campaigns, automatic notifications, categories and opt-out.
- Support and growth: tickets, live support chat, referral codes, remote config, player activity.
- Games: many games on one server, game settings with rooms, entry fees and prizes, matchmaking hooks, the Star Catcher sample with tic-tac-toe.
- Friend request rules: requests per day, most friends, invite expiry and a wait after a rejection, per player tag, with extra requests and slots from economy metas, refuse or trim over the limit, translated JSON errors and `base_friend_rules`.
- Player reports not tied to a chat message, with a review page, internal notes and the same decisions as chat reports, admin-set report rules; `base_report_player`, `base_my_reports`.
- Voice chat tokens: `voice_token` for matches, parties and open rooms, LiveKit and Rastaar comms providers chosen in «سرور ویس» with sealed secrets and a connection test, per-game switch and room size, allowed and listen-only player tags.
- Friend gifts: give a friend an item or currency from the inventory or buy them a shop product (coins, gateways, stores), only things they do not have; giftable per item, item type and product; friends, friendship age, mutual friends, blocks, levels and account ages; daily sender, recipient and pair limits per player tag with purchasable bonus metas; instant or accept/decline delivery with expiry and returns or refunds; a filtered message; inbox, push and live notices; `Gift:Sent`/`Gift:Received`; admin log, reverse, report and settings in «هدیه به دوست»; client RPCs `economy_friend_gift_options`, `economy_friend_gift_send`, `economy_friend_gifts`, `economy_friend_gift_accept`, `economy_friend_gift_decline`, `economy_friend_gift_cancel`. Gift purchases no longer count as the sender's own purchases of the product.
- Personal offers: an admin pool of offers over shop products; each player gets their own daily set (admin period, reset time and zone, count, weights, tags, levels, metas, no-repeat window, bought cooldown, free or paid rerolls) and entry offers (first entry, level, meta, tag, account age or a return after a break) with a personal countdown; bought through the normal shop flow at the offer price with per-offer limits; client RPCs `economy_offers`, `economy_offer_buy`, `economy_offers_reroll`, `economy_offer_seen`; console «پیشنهادهای ویژه» with preview, report, settings and a player card.
- Meta relations: when a player meta reaches a value (>, ≥, =, ≤, <), change other metas (add or set) and give a prize or one from a prize group, once, again after a drop, or every time with a cap; checked on every meta change with an admin chain depth; `MetaRelation:Completed` event; client RPC `economy_meta_relations`; console tab «رابطهٔ متاها», a meta studio side panel that shows and edits everything feeding and fed by a meta, «تغییر متا» on the player card. Purchases, gift codes, admin and game prizes that give metas now also update level tables.
- Console navigation: sidebar groups that fold and remember their state, and tabbed pages (metas, tasks, prizes, events, banners, notifications) with one address per tab; the old addresses such as `#/economy/prize-groups` redirect to the matching tab, and Ctrl K finds tabs too.
- Economy overview: a KPI row (30-day revenue with a sparkline, today's payments, events in 24 hours, waiting prizes, each with the change against the previous period), the catalog grouped like the sidebar with one clickable tile per page and an active count, a 30-day revenue or payment chart, a payment status bar and empty states that link to payment settings or the shop; tiles and sections follow the admin's permissions.
- Setup wizard as a centered stepper: steps and progress on the side, one step per screen that fits 1280×720 without scrolling, extras under «تنظیمات بیشتر», a live brand preview, «ذخیره و مرور نهایی» before the summary with an edit link per step.
- Private chat quota (off by default): a free daily count of direct messages or new chats with an admin reset time and zone, message packs sold as shop products through an economy meta (stacking, optional expiry, free first or packs first), unlimited players by tag rule, item or subscription meta, optional free replies, separate or free quota for friends, groups and rooms on request; refusals are JSON with the reset time and the pack products, with an optional inbox notice; client RPC `base_chat_quota`; console «سهمیهٔ پیام خصوصی» with rules, settings, report and a player card. Migration `20261128000000-base-chat-quota.sql`.
- Game entry requirements: a game or a room can ask for items (any or all), player tags, no excluded tags, a level and meta values, and can use up a ticket item or an amount of a meta on entry, given back on a leave before the start or a cancelled match unless the admin keeps it; per set paths (matchmaking, bot, friend), inheritance, locked or hidden rooms, offered products and a refusal message; `REQUIREMENTS_NOT_MET` with the missing requirements and products from `economy_game_join` (new `path`), the matchmaker hook and `gamecatalog.Enter` (new `Entry.Path`); `gamecatalog.Check` for bot and friend-room RPCs; `economy_games` shows requirements and per-path eligibility; console requirement boxes in the game editor. Migration `20261129000000-economy-game-requirements.sql` (also adds the item source `game`). Forks with their own bot or friend-room code should pass `Path` to `gamecatalog.Enter` and may call `gamecatalog.Check` before making a match.
- News: draft, review, published, archived and rejected articles with an end time, tags, a Tiptap rich editor (HTML cleaned to the editor allowlist on the server), reactions with an admin set, a review queue with bulk approve and reject, and SEO fields (slug, meta title and description, keywords, canonical, share image, noindex) with a search preview. Webhook sources (`POST /v2/publication/news/ingest/{key}`) with a static token or an HMAC-SHA256 signature, bodies up to 256 KB (413 `PAYLOAD_TOO_LARGE`), JSON path mapping (a cover may be a string or an object with `url`, `src` or `href`), dedupe and update rules, review or auto publish, rate limits, optional cover copy and an ingest log. A notice goes out once when an article becomes visible (in-app, push or both) plus a live socket notice (code 1320). New RPCs `publication_news_unread`, `publication_news_react`, `publication_news_reaction_types`, `publication_news_by_slug`, `publication_news_comment_delete`; list filters for tags, expiry and unread. Public JSON, `sitemap.xml` and `rss.xml` under `/v2/publication/public/` stay off until switched on in the news settings.
- Friends and profile over the socket: RPCs `base_friends_list`, `base_friends_add`, `base_friends_remove`, `base_friends_block`, `base_account_get`, `base_account_update` and `base_users_get` do the Nakama friend, account and user calls through the runtime and run the before/after hooks registered in `internal/hookchain` (`RunBefore`, `RunAfter`, `RunAfterIn`), so friend limits, cooldowns and account rules apply the same as over HTTP; answers use Nakama's JSON; optional `lang` in the body for error texts.
- SMS login code pattern: Kavenegar (`otpTemplate` with `%token` = code and optional `%token2`/`%token3`/`%token10` = minutes or game name, sent through `verify/lookup.json`) and sms.ir (`otpTemplateId`, code variable default `CODE`, optional minutes and game name variables, sent through `/v1/send/verify`) in their own box «پیامک کد ورود (پترن)» on the provider card and in the setup wizard; only login codes use it, other SMS stay plain text, and with no pattern codes go out as plain text as before. The SMS test box can send a test code through the pattern (`POST …/providers/{id}/test {to, otp: true}` returns the mode and the code), and sandbox log lines say which mode a live send would use. The setup wizard's «ذخیره و ارسال آزمایشی» now keeps the result on screen after it creates a new service, says so when the save fails, and works with test mode off («ذخیره و ارسال واقعی»). No migration; fill the pattern after your operator approves it.
- comms user tokens: RPC `comms_user_token` signs a short-lived HS256 user token (`kid`, `aud` = App ID, `iss`, `sub` = Nakama user id, `name`, `iat`, `exp`, `jti`) for chat, calls and meetings in Rastaar comms; App ID, issuer, token key ID and sealed token secret in «سرور ویس» (comms), its own switch (off by default) that works with voice off, lifetime 300 s (60–600) and 10 tokens a minute per player; «امتحان اتصال» exchanges a test token at comms `POST /v1/sessions`. Migration `20270104000000-base-comms-user-tokens.sql`.
- Communication packs for in-match chat on the sticker packs: kind (sticker, text, gif, emoji), chat and/or match use, item text and client asset id; RPCs `base_comm_packs`, `base_comm_favorite`, `base_comm_favorites`; `internal/commpacks` for match handlers with a per-player cooldown (4 s gap, 6 per 30 s, 30 s lock by default, admin settings «پیام سریع بازی»), one-minute message dedupe and per-match channels staff can close or mute per player («گفتگوی مسابقه‌ها»). Staff voice mute: «اتاق‌های ویس» lists live rooms and mutes a player through LiveKit `UpdateParticipant` or the comms mute API; `voice_token` answers `canPublish:false, staffMuted:true` until the room ends. Migrations `20270107000000-base-comm-packs.sql`, `20270107000001-base-voice-moderation.sql`.
- Cluster mode on Redis (off by default).
- Updates page: this server's version and the parent repo's new commits, releases, changed files and warnings, with a copy-only update guide; build info is embedded by `build/buildinfo.sh` and the base commit is recorded in `build/upstream.json` by `build/upstream-sync.sh record`.

### Removed
- Unity package registry: the developer kit's «پکیج‌های یونیتی» page and its settings card, the `/upm` registry routes, the `/v2/devkit/packages` publish API and the `upm:read` / `upm:publish` scopes. The Unity SDK installs from git only; the console's SDK page (`#/system/sdk`) shows the line. Migration `20270129000000-devkit-drop-upm.sql` removes the two scopes from the scope list and from API keys, drops the `packages` block from the devkit settings and clears non-custom `UPM_*` error text overrides. It keeps the `devkit_package_version` rows and the archives in storage (`devkit/upm/…`); nothing reads them any more, so delete them by hand if you want the space back. CI jobs that published with `upm:publish` must stop.

### Migrations
- Many new `migrate/sql/2026*` files for the base, economy and publication plugins; run `nakama migrate up` (the Docker image does it on start unless `NAKAMA_MIGRATE_ON_START=false`).

### Environment
- `ECONOMY_SECRET_KEY` (32+ characters) seals provider secrets and the optional GitHub token; storage, payment and game variables are listed in `build/nakama-start.sh`.
- `BASE_UPDATES_API_URL` (optional) replaces the GitHub API address, for tests only.
